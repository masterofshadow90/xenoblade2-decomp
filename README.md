# Xenoblade Chronicles 2 Decompilation Project

An open-source, matching decompilation project for **Xenoblade Chronicles 2** on the Nintendo Switch.

The main objective is to reconstruct the original C++ source code from the compiled binaries.

## 🎮 Base ROM Information

| Parameter | Detail |
| :--- | :--- |
| **Game** | Xenoblade Chronicles 2 |
| **Platform** | Nintendo Switch (ARM64 / AArch64) |
| **Version / Revision** | v2.1.0 ) |
| **Region** | USA / Europe (Global Update) |
| **Title ID** | `0100E95004038000` |
| **Build ID** | `F77F1559371C0EC6D50E78774AC59D95` |
| **Binary Format** | NSO Compressed Patch (LZ4 Delta) |
| **Compressed Size** | 6.42 MB (6,738,079 bytes) |

⚠️ **Critical Note:** Using any other update, regional patch, or revision will shift memory addresses and cause the decompiled code to mismatch.

## 📂 Repository Structure

```text
xenoblade2-decomp/
├── asm/               # Extracted ARM64 (AArch64) assembly files from the original game
├── baserom/           # Target folder for the uncompressed 'main.elf' binary (Never commit this!)
├── build/             # Output directory for compiled object files and final binaries
├── config/            # Splat configuration files for binary splitting and symbol mapping
├── data/              # Raw database files, Ghidra symbol exports, and string dictionaries
├── src/               # Reimplemented C++ source code matching the original functions
└── tools/             # Python automation scripts, disassembly helpers, and split utilities
```

Each major directory serves a specific purpose in the decompilation pipeline:

* **`asm/`**: Contains raw assembly code generated by the splitting tools. This acts as the reference for functions that have not yet been decompiled into C++.
* **`baserom/`**: Place your dumped executable here to allow building tools to verify byte-matching accuracy.
* **`build/`**: The workspace for the compiler toolchain. It stores the temporary object files (`.o`) and the final recompiled binary used for matching verification.
* **`config/`**: Houses the configuration profiles used by **Splat** to slice the monolithic game binary into individual files, sections, and functions.
* **`data/`**: Houses raw forensic data extracted from the binary. This includes Ghidra symbol table exports, uncompressed BDAT database structures, and string dictionaries used as reference mapping before code reconstruction.
* **`src/`**: The core of the project. This is where the reconstructed C++ code lives, carefully written to compile into identical machine code.
* **`tools/`**: Contains Python automation scripts, asset extractors, and helper utilities that streamline the build process and symbol extraction.

## 🛠️ Requirements

To successfully set up the environment and build the project, you will need the following dependencies:

### Toolchains & System Dependencies
* **devkitPro (devkitA64 v16.1.0):** The AArch64 cross-compiler toolchain required to compile code for the Nintendo Switch.
* **MinGW-w64 / GCC (Host Compiler):** Required to compile local helper tools and native automation binaries.
* **Make:** Build automation tool to orchestrate the compilation process.
* **Git:** For source control management and repository synchronization.
* **Python 3.x:** Required to execute build automation scripts and splitting utilities.

### Python Libraries (Pip Dependencies)
* **capstone:** Lightweight multi-platform disassembly framework used by Splat to dissect instructions.
* **pyelftools:** Pure-Python library for parsing and analyzing ELF files and object data metadata.

### Reverse Engineering & Diffing Tools
* **Ghidra:** Used as the primary interactive disassembler and decompiler to analyze the binary structure and map symbols.
* **NxFileViewer:** Used to explore Nintendo Switch game files and extract the original executable.
* **objdiff:** Used for real-time visual diffing and bit-per-byte matching comparison between the original assembly and recompiled C++.
* **Splat:** The binary splitting framework used to dissect the monolithic game executable.
